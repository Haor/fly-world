# 嗅觉寻食

嗅觉和寻食辅助默认开启。关闭辅助保留感觉输入，关闭嗅觉则恢复原有探索驱动。气味场开关只控制显示。重置清空嗅觉历史与需求状态，保留开关设置；暂停时感觉适应也暂停。浏览器通过已有 USB 桥接同步身体姿态。断开电脑后的固件仍使用本地玩具规则，本次未增加离线寻食。

点击“换个起点”，会在远离果实的随机位置与朝向重新初始化神经状态；普通“重置”恢复原始起点。两者都保留暂停状态与输入设置。

## 感知与控制

静态气味场为 `25 * exp(-distance_mm / 7)`。左右触角在身体中心前方 0.9 mm、左右各偏移 0.3 mm 处采样。这些距离和气味场参数由工程设定，未按真实受体进行标定。各侧维护时间常数为 2 秒的指数基线，从原始值中扣除基线的 0.6 倍，限制在 0–25 Hz 后分别输入 L、R 标注的 ORN_DM1；无侧别标注的神经元不接收嗅觉输入。气味场显示的是适应前数值。

辅助只接收两个局部样本、近期变化、接触、着地、需求、时间与驱动增益，不能访问食物坐标。它以 0.25 秒神经时间平滑左右归一化差值和浓度变化率，通过 DNa02 输入向气味较强的一侧转向。闻不到气味，或气味减弱且左右信息不足时，交替转向进行局部搜索。转向越强，LC9 步行驱动越低。身体仍由既有神经输出解码器更新；辅助不会直接写位置或朝向。

休息、飞行、饱足，以及启用味觉时接触食物，会停止寻食辅助。接触产生味觉输入；进食仍要求实际接触、尚未饱足和足够的 MN9 神经输出。饱足沿用已有饥饿规则。饱足只停用寻食辅助，不代表其他神经活动停止。

这是人工编写的导航策略。刺激下行神经元不会使策略变成连接组的自主决策，目前没有证明单靠双侧 ORN_DM1 输入就能可靠寻食。尚未模拟风、湍流气味、多种气味身份和学习偏好。云端协议通过 `population-hz/2` 保留左右独立输入。

## 验证

- `node --test tests/*.test.js`：侧别映射、镜像与旋转对称、感觉适应、暂停重置、独立开关、需求约束、零神经输出不产生运动，以及云端编码协商。
- 导航几何测试在 40 组固定种子的随机食物位置、出生位置与朝向中，对比正常嗅觉、无嗅觉与左右交换。使用简单运动执行器，只验证辅助策略，不代表神经网络验证。
- `FORAGE_TRIALS=3 FORAGE_SECONDS=10 node tests/foraging-loop.mjs`：完整保留本地连接组测试，三个模式共享出生位置与神经随机种子，分别开启辅助、关闭嗅觉、关闭辅助。记录初始姿态、首次接触、首次进食、最终距离和放电数；首次进食或超时结束。这是小样本功能对照，不能用来估计普遍成功率。

CSV 观察记录包含左右输入率、气味变化率和辅助状态，仍保留最近 12 秒神经时间的窗口。

行为背景：[步行果蝇的气味出现、消失与局部搜索实验](https://elifesciences.org/articles/37815)。该实验还使用了风向线索，本实现未模拟风。

## 验证结果 — 2026-09-08

保留连接组的 CPU 仿真中，辅助开启的 3 组均找到食物，首次进食分别为 3.98、6.11、7.56 秒神经时间。相同起点关闭嗅觉或关闭辅助，10 秒内均未找到食物，各为 0/3。这是固定种子的小样本对照，不能估计普遍可靠性。[机器可读结果](foraging-results.json)。

浏览器 WebGPU 也在随机起点重置后完成进食。独立开关、暂停重置和 USB 同步已检查。未联调真实云端服务，也未重新测试实体按键；风和可靠避障不在本次验证范围内。
